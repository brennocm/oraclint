# NS-K8S-002: Container securityContext not hardened

| Severity | Target | Status | CWE |
|---|---|---|---|
| medium | k8s | stable | CWE-250 |

## Description

Fires once per container or init container that lacks any of:

- `allowPrivilegeEscalation: false`;
- `runAsNonRoot: true` (container level, or inherited from the pod's
  `securityContext` when the container does not set it);
- `readOnlyRootFilesystem: true`.

The message lists exactly which settings are missing. (This rule also covers
what was planned as NS-K8S-003, so that one container yields one finding.)

## Why it matters

These are the core settings of the Kubernetes "restricted" profile. They limit
what an attacker can do after exploiting the container: no setuid escalation,
no root inside the container, and no persistence by modifying the image's
files. The node writes to its root directory, so mount a writable volume there
when enabling a read-only root filesystem.

## Vulnerable example

```yaml
containers:
  - name: node
    image: smartcontract/chainlink:2.69.0
```

## Fixed example

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 14933
containers:
  - name: node
    image: smartcontract/chainlink:2.69.0
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
```
