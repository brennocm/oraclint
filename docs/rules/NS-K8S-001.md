# NS-K8S-001: Privileged pod or host namespace

| Severity | Target | Status | CWE |
|---|---|---|---|
| high | k8s | stable | CWE-250 |

## Description

Fires for workloads (Pod, Deployment, StatefulSet, DaemonSet, ReplicaSet,
ReplicationController, Job, CronJob) whose pod spec sets `hostNetwork`,
`hostPID` or `hostIPC` to `true`, mounts a `hostPath` volume of a container
runtime socket or system directory of the node (`/var/run/docker.sock`,
`containerd.sock`, `crio.sock`, `/`, `/proc`, `/sys`, `/etc`, `/root`, `/dev`,
`/boot`, `/var/lib/docker`, `/var/lib/kubelet`), and for every container or
init container with `securityContext.privileged: true`. Objects inside a
`kind: List` document are checked too (as for every Kubernetes rule).

## Why it matters

These settings are forbidden by the Kubernetes "baseline" Pod Security
Standard because they break the isolation between the pod and the worker
node. A compromised container could read other pods' traffic, processes and
secrets on that node.

## Vulnerable example

```yaml
spec:
  template:
    spec:
      hostNetwork: true
```

## Fixed example

```yaml
spec:
  template:
    spec:
      containers:
        - name: node
          image: smartcontract/chainlink:2.69.0
```
